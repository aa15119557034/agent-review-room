# 世界第一版：确定性工程验收场景

2026-11-16，林离；X-41 实施准备。依据 [ADR-008](design/ADR-008-世界-第一版.md)，进度见 [任务板](世界-任务.md)。本文是待实现的验收要求，**没有已通过的世界测试**，不提前定义 C-53 的类型、字段名或产品参数。

## 共用输入

两位居民 A/B、玩家 U、客厅/厨房/私人房间、一本书、一口锅、两份食材、零份成品。注入模拟时钟与现实日时钟，居民策略和模型返回可控。配方、耗时、作息和预算窗口使用合并后的契约/规则值。测试先禁用外部模型，再用可控制迟到返回的假节点，最后单独做真实模型验收。

## 六组核心场景

| 场景 | 输入与故障注入 | 通过标准 |
|---|---|---|
| 唯一物品争用 | A/B 同处客厅，按已知入队顺序申请同一本书；重送原动作；再用同 ID 提交不同内容。 | 只有第一个合法请求取得书；另一方有明确结果。重送不重复事件、观察或熟悉度变化；同 ID 异内容不变成另一动作。 |
| 烹饪取消与完成竞争 | A 开始做饭，完成前取消，再推进越过完成时刻；另测取消与完成竞争、提交后响应丢失重试、事务中失败。 | 取消释放锅，不产出食物；取消/完成只有一个终态。材料按已定规则结算，不多扣、多退；状态、事件、观察一起提交或回滚。 |
| 秘密移动与转述 | 两人先看到书在客厅；B 离开，A 将书移走；分别构建上下文，再向 B 转述。 | A 获得亲历，B 保留旧观察或不知道。模型实际收到的上下文、回顾、回查、校验旁白均不泄漏。转述注明来源，不制造亲历、不改变物品真值。 |
| 忙碌时延后邀约 | U 邀请忙碌的 A 一起准备餐桌；固定回应稍后；到期前保存重启，到期时分别测空闲、仍忙、已取消。 | 延后成为可恢复的约定；到期处理一次，实际行动或明确推迟/失败；取消后不复活，不能只说台词。 |
| 暂停/重置/切换后迟到 | 模型请求挂起，执行暂停继续、重置、备份恢复、资料切换；新状态故意满足旧动作条件，然后释放旧结果。 | 旧代次仍作废。新局不继承旧活动、约定、观察和熟悉度；同局暂停则保留生活状态。旧场景选项也不能静默执行。 |
| 真实用量与世界恢复 | 固定现实日期与小额预算，派发前占名额；快进、重置、恢复早期备份、重启后再次请求；再推进现实日期。 | 世界变更不返还已用额度，达到上限就不派发；真实新日按规则开放。旧请求不污染新日计数；规则生活继续。 |

世界/局身份与请求代次分别验证。规则动作使用权威状态裁决；角色认识按其观察、来源与时间验证，允许旧认识。完成声明必须关联已提交且可见的结果；回忆和转述不能因校验而被改成全貌真值。

## 提交与维护故障

1. 在状态、事件、观察提交中途注入异常，确认全笔回滚。
2. 提交已成功但响应/通知未送达时中断，恢复和重送后只生效一次。
3. 世界运行中备份：停止 tick/新动作/新认知，已接纳写入收束后再快照；不在占有写队列时等待自身排空。
4. 备份成功、失败、取消分别测原先运行/暂停，以及期间用户改变意图；不得覆盖用户后续暂停/继续。临时维护暂停不被误存成永久用户意图。
5. 创建恢复副本不切活动库；真正切换后旧回调不写新实例。退出和休眠冻结模拟时间，恢复不补算停机经历。
6. 检查同一活动库不会启动两个世界调度者；世界资源备份/恢复符合采用的附件方案。
7. 进程强制终止后重开，核对已提交事件序号、物品数量、活动和约定。正常关闭恢复测试不能代替这一项。

## 测试落点与证据

- `packages/core/test/`：纯规则，显式推进时间。
- `packages/db/test/`：真实临时 SQLite 与 WriteQueue，旧库迁移和原子性。
- `apps/desktop/test/`：服务注入时钟和依赖，维护、代次、预算及节点优先级。
- `apps/desktop/e2e/`：真实 dispatcher、DB、HTTP adapter 与可控假节点，最后接 GUI/真机流程。

沿用 `node:test`、`node:assert/strict` 与 `tsx`。测试文件平放相应 `test/`，让现有包脚本和统一验证器能发现。时序使用可释放闸门和完成事件，避免固定 sleep。秘密移动测试同时断言 A 能看到目标事件，防止整条链未执行却误报“不泄漏”。

现有参考：`packages/db/test/run-lifecycle.test.ts` 的终态互斥/事务回滚，`apps/desktop/test/workspace.test.ts` 的备份恢复，`apps/desktop/test/chat-ipc.test.ts` 的挂起请求和注入时钟，`apps/desktop/e2e/fake-node.ts` 的迟到返回和请求捕获。它们提供测试写法，不代表世界已有相应能力。

每轮证据至少记录 commit、实际命令和结果；真机记录运行版本、环境和步骤；模型记录是否使用假节点或真实节点；性能记录硬件、窗口大小、运行阶段与三类开销。未测项直接标未测。

最终可玩验收仍按 ADR 的 10 项体验进行，工程矩阵不能代替角色是否自然、画面是否清楚、生活是否能接续的实际体验。
