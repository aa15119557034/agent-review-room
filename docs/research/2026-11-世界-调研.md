## 1. 结论

建议第一版选择“共享小屋”：少量地点、两个角色、少量可争用物品、若干有起止和中断规则的日常活动。共享世界由代码持有权威状态，每位角色只获得自己可感知的事件，模型负责提出行动和表达。角色独处和多人互动使用同一个世界内核，不分别建设两套生活系统。

参考材料关于事实、行动、记忆、情绪和关系的边界值得保留，但它把 M0–M6 运行时视为已有 V0.3 基线，当前仓库也没有这个世界运行时。需要先补世界状态、感知、活动、并发裁决、时间与恢复契约。依据见原文第 5–7、17、20、23、26 节和第 3 节的仓库核查。

建议在 ADR-008 中明确：保留现有 TypeScript/Electron/节点边界，不因参考文档的 Python 示例整体迁移架构；首版用规则 Observer，真实认知通过现有节点能力做受限接入；不同时建设本地常驻模型、图谱、自动学习和后台服务。此处是减少首版依赖的工程取舍，不是原文强制要求。

### 2.1 外部现实接入和预算参考

Home Assistant 的 Assist API 只读写向 Assist 暴露的实体，不提供管理操作；它的管理员 API 是另一套更高权限接口，不受同一实体暴露清单约束。[S11]、[S12] 本项目可借鉴显式来源/实体/操作白名单：天气查询、日历读取、发消息和控制设备各有独立权限。虚拟角色的世界行动许可不产生现实工具许可。

OpenHands SDK 有执行前确认策略以及成本、迭代预算。其成本检查位于 step 之后，官方客户端文档也说明单步可能越过预算，因此这不是严格的调用前金额封顶。[S13]、[S14]、[S15] 本项目应借鉴统一动作门控和多维预算，不以模型自报风险或一次事后费用检查代替授权与硬上限。

后续接入外部现实来源时，建议先做一种只读来源，保存来源 ID、收到时间、来源报告的发生时间、有效期和原始证据引用。消息或网页中的命令只是内容，不获得权限。外部写入留到节点执行能力和授权/回执契约具备之后；未知执行结果需要核对，不能盲重试。现有权限能力缺口见第 3 节，相关拟议执行语义见 [ADR-007 第 5.1、7 节](../design/ADR-007-Super-Agent-工作台.md)。

### 3.1 世界历史与秘书长期记忆

建议保留 ADR-003，明确三种不同用途：

1. 世界状态、已提交事件和角色观察记录属于世界运行数据，可自动持久化用于恢复和审计；世界当前状态不必每 tick 等人工批准。
2. 把经历升级为某位秘书的稳定身份、长期关系事实或个人记忆正文，仍需 `候选 → inbox → 用户确认 → 正文`。现有项目笔记允许直接写入，不能用来绕开这条边界。[ADR-005](../design/ADR-005-项目笔记和换窗口.md) 32–42、169 同样区分两者。
3. 若希望自动把角色过去观察记录供跨会话认知当“世界内回忆”，ADR-008 必须明确允许的范围、来源标签与撤回策略。这是需要明确采纳的记忆政策，不能只把个人记忆改名为 world log 就规避确认。第一版默认不自动晋升个人长期记忆。

所有世界记录保留 `world_id` 和角色归属；虚拟经历不能被表达成现实世界已经发生的行为。L2/L3、摘要、导出和 provenance 回查都要遵守角色可见性，不能借全局审计库越过感知边界。

## 4. 第一版有三种切法

以下是建议方案与相对复杂度，不是工期承诺；都保留角色生活和多人共享目标。

| 方案 | 能看到的结果 | 主要成本与限制 |
|---|---|---|
| A 共享房间 | 两个角色、一个公共场景、少量物品，拿放、休息、交谈；文本事件呈现 | 最小闭环，适合先证明争用和恢复；难以验证跨房间视野与秘密事件，生活内容较少。 |
| **B 共享小屋，建议采用** | 两个角色、约三个相连地点、少量物品；移动、拿放、休息、一种耗时活动、交流；角色可见性和恢复完整 | 增加地点连接、活动状态与资源占用；足够验证生活连续性和多人影响，不需要物理引擎、大地图或经济系统。 |
| C 共享小屋加现实接入和持续服务 | B 加一种真实只读来源、退出桌面后的运行服务；后续才开放真实外部动作 | 多出服务生命周期、独占写入、设备身份、来源授权、配额与回执；首版失败面显著增加，建议后置。 |

建议先做 B 的无模型运行闭环，再通过现有节点接入受限认知。规则角色用于确定性验收，不冒充真实模型的自然度；节点模型接入后再评估自然活动和互动质量。来源与取舍依据：用户目标见概念入口；公开机制见第 2 节；现有缺口见第 3 节。

## 5. 建议 ADR-008 冻结的最小世界契约

以下是领域设计要求，**不是本 PR 新增的 API/TypeScript schema**；最终命名由 C酱的独立契约 PR 确定。

### 5.1 状态所有权与主体视野

| 对象 | 最小语义 |
|---|---|
| 世界 | 身份、世界时间、事件提交位置、规则版本、运行/暂停状态。 |
| 地点 | 稳定 ID、相邻地点、通行条件；首版采用连接关系，不做连续物理模拟。 |
| 角色 | 身份、位置、当前主要活动、必要资源；模型不直接写位置或结果。 |
| 物品 | 稳定 ID、数量/可用性及唯一位置或持有人；背包列表是派生视图，避免双重归属。 |
| 活动 | 参与者、占用资源、起止时间、状态、中断与结束原因。 |
| 已提交事件 | 稳定 ID/顺序、世界时间、动作与原因、权威来源、规则版本。 |
| 角色观察 | 接收角色、感知内容、感知时间、证据和不确定性；听说与亲眼观察可区分。 |

世界权威状态经感知规则投影，再进入角色认知。角色关系估计有方向，A→B 不自动等于 B→A。原文第 27 节 `PrivateWorld` 应落实为角色可读视图，不能直接把全局世界快照塞给每个角色。

原始输入日志证明“接收过该输入”，不证明其中陈述为真。建议明确陈述、观察、意图和已提交结果的语义；例如“B 说门已锁”不能自动更新门锁状态。该要求落实原文第 5.3 节的外部来源纪律，并澄清第 12 节 Raw Event“事实地位最高”的作用域。

### 5.2 动作、活动与资源竞争

动作从提案开始，经当前状态验证才能接受；耗时动作进入活动，完成/取消/失败后产生真实结果。接受、开始与完成分别记录。首版建议每个角色最多一个主要活动，交流是否占用活动由规则明说。

首版使用一个世界写入队列。提交时原子检查前置条件和资源占用，并提交状态、事件和待投递记录；提交成功后才发布。动作使用稳定唯一 ID，重试和事件消费都去重。读到的世界版本用于溯源，但执行检查相关前置条件，避免无关 tick 使所有提案失效。

模型任务必须关联输入事件、角色、上下文版本、截止和取消状态。事件接收和停止操作不能堵在慢模型请求后面；迟到提案在最新状态下重验。已取消任务不能因迟到结果复活。世界内部动作可由同一存储事务裁决；外部动作不能声称跨网络 exactly-once，未知结果应核对。[ADR-007 第 7 节](../design/ADR-007-Super-Agent-工作台.md) 已提出可参考的故障窗口。

表达层只能叙述许可的事实与行动结果。交付前对关键完成声明、承诺和引用做一致性检查；异步自然度评价不能补救已交付的虚假完成声明。原文第 16 节有禁止新增事实的原则，第 18 节事后评价还不能代替这个交付边界。

### 5.3 时间、停机与回放

建议首版采用以下明确行为，交给 C酱在 ADR-008 确认或替换：

- 后端活着、用户不操作：世界继续按规则推进，不要求每 tick 调模型。
- 显式暂停世界：冻结世界时间和活动；停止新增认知任务并使不适用的迟到结果失效。
- 主进程退出或机器休眠：首版暂停模拟时间，恢复后继续；不补写一夜未实际模拟的复杂经历。最小化窗口与真正退出进程必须区分。
- 重启恢复：快照记录已应用事件序号，按稳定顺序恢复已提交结果；不重新调用模型、抽随机结果或重复外部动作。
- 若以后要现实时间驱动的补算，逐条定义可解析计算的资源变化、过期计划和补算上限；另开运行身份进行“重新仿真实验”，不改原历史。

暂停而不补算是本次建议，不是用户已经确认的偏好。它让第一版先解决可解释恢复；24 小时运行以后通过常驻服务部署改变可用性，不用伪造离线活动补连续感。原文第 6、20 节尚未冻结这些语义。

### 5.4 有界随机与事实边界

原文第 5.2 节允许代码控制的偶发世界事件、NPC 行为；第 36 条第 11 项却写随机性只进入 Expression，存在直接作用域冲突。建议 ADR-008 明确：世界规则允许可审计随机，记录规则版本和抽样结果/必要随机状态；恢复读取已提交结果。表达随机只影响措辞，不改变既定事实、权限和行动结果。

第一版随机事件不是必需依赖。可以先固定规则验证，再加入一个受控随机场景；seed 本身不代替事件顺序、规则版本和结果记录。

## 6. 无人值守时的主动性与费用

原文第 15 节已有冷却、打扰成本、未回复抑制和安静时段；第 9、20 节已有路由与故障降级方向。建议把它们落实为可持久化的门控与预算，避免角色相互聊天无限唤醒。

- 规则推进不消耗模型调用；一段活动只在有决策价值的事件或阶段变化时考虑认知。
- 初期全世界最多一个认知请求并发；每次互动有有限轮数、冷却、去重与截止。角色自己发出的事件不无限递归触发自己或对方。
- 无人值守模型功能启用前必须配置日调用次数或 token 预算、单次上下文/输出上限、重试上限；参数是可调整配置，不从开发者当前账户额度推导。
- 派发前预留预算，完成后按可靠 usage 结算；未知用量不能清零释放。能可靠估价的 API 才同时设金额预算；订阅节点不能可靠报告金额时，明确报告调用/token 限制和金额未知，不宣称精确费用封顶。[S14]、[S15]
- 预算耗尽、节点离线或 Observer 故障时，保留规则世界和状态保存，暂停新的模型认知；合并/失效过期认知候选，恢复后不集中补跑。
- 游戏内角色聊天与向江浩发送真实通知分别计算。用户未响应、安静时段、日通知预算继续限制外部打扰，不以“关系张力”扩大权限。

这里提出预算机制，没有给尚未测量的模型推荐价格、显存效果或自然度成绩；也不把 #224 中开发协作的“额度暂时无限”写成产品运行预算。

## 7. 与 ADR-007 的关系和实施顺序

建议两个方向共享现有节点和控制面的能力边界，但区分领域：世界 Activity 管虚拟角色行为，Goal/WorkItem 管现实成果任务。模拟“写信”成功不等于现实邮件已发送。将来确需执行现实任务时，通过显式授权和来源关联提交给目标执行域，不能由世界 Reducer 直接操作外部工具。

最小共享模拟不依赖 ADR-007 全套运行时落地，也不提前实现第二套通用工作调度器。接入现实工具时再依赖其授权、取消、回执及恢复能力；这些仍需独立契约 PR。[ADR-007](../design/ADR-007-Super-Agent-工作台.md)、[Phase 2 候选任务](../phase2-候选任务.md) 是提议来源，不是已交付能力。

建议顺序：

1. X-39 入库：原始材料、范围、仓库事实和本方案；C酱在 PR 回复关键取舍。
2. C酱写 ADR-008：采用或修改 B，冻结状态、感知、活动、时间、记忆边界、数据落点和进程所有权；明确与 ADR-003、ADR-007 的关系。江浩合并为采纳。
3. C酱单独提交契约：世界命令/事件/视图，必要节点扩展；新类型仍放 `packages/schemas/`。契约合并前 UI 对 mock，不按猜测写后台。
4. 林离实现规则世界、持久化和故障验收；C酱界面与交叉评审。世界新后台文件的本轮分工以 #224 最终采纳内容为准，已有非世界文件的改动在 PR 明说。
5. 接一种节点认知、模型预算和个人记忆候选确认；先运行真实场景，再考虑丰富情绪/关系动力学。
6. 后置现实来源、常驻部署、复杂记忆召回和经验学习。自动策略发布不属于第一版；原文附录 A 本来也要求先生成候选。

存储建议优先保留 ADR-003 的 `<AgentRoom>/world/` 数据域，并明确一个世界写入者。具体使用独立 SQLite 或其他布局在契约前决定；备份、恢复、路径切换和数据版本必须覆盖世界数据，不能直接宣称现有备份已经包含新目录。

## 8. 最小验收场景

以下是待实现的验收要求，**本次没有执行，不记录为通过**。

| 场景 | 必须观察到的结果 |
|---|---|
| 争用唯一物品 | A/B 同时拿唯一的书或锅，仅一方成功；另一方得到明确结果，位置/持有人唯一。 |
| 耗时活动与中断 | 做饭开始不立刻产生食物；完成只生成一次；取消按规则释放资源并结算已消耗材料；重启不重复产物。 |
| 秘密移动 | A 在 B 不在场时移动钥匙；B 的当前视图、摘要、L2/L3 和证据回查都不泄漏新位置。 |
| 告知与真值 | B 听 A 说钥匙位置，记录获知来源；谎言/误报不直接改变世界真实位置。 |
| 迟到认知 | 角色活动已取消或前置资源已变，旧模型结果不能直接落地或复活已结束活动。 |
| 显式暂停再恢复 | 暂停期间不启动活动、扣资源或发送真实通知；恢复后到达的旧模型结果按契约重新校验或作废，不能自动复活。 |
| 提交故障 | 状态/事件提交前后强制终止，恢复没有幽灵经历、重复扣资源或重复行动。 |
| 停机与时间变化 | 最小化、退出、休眠、系统时间跳变行为与设计一致；不补跑通知风暴、不伪造离线经历。 |
| 节点与预算故障 | 所有模型离线或预算归零，规则世界仍可推进/暂停/恢复；没有无限模型重试。 |
| 个人记忆 | 世界日志可恢复，未经确认的候选不能写进个人 core/notes/journal；审批撤回后不能迟到晋升。 |
| 现实副作用 | 模拟行动不会隐式发送真实消息/控制设备；回放不重做真实动作。 |
| 来源与范围 | 外部内容不升级为指令；另一角色/世界的记录不能通过检索与引用串入。 |

认知质量另做真实模型评测：活动是否合理、是否重复、互动是否自然、主动是否有价值。不能用规则测试通过替代自然度成绩，也不靠 Evaluator 自评分宣称事实正确。

## 9. 请 C酱收敛的决定

建议采用 B，并确认下列具体默认值：单世界写入者；首版不强依赖本地 Observer 模型；无人交互时继续规则运行；进程退出/休眠时暂停世界时间；保留 ADR-003 个人记忆确认；现实写操作和常驻服务后置。

请在 ADR-008 或本研究 PR 逐项接受、修改或给替代方案。尤其需要明确：世界内历史如何供角色回顾而不绕过个人记忆确认、world 数据与现有备份恢复如何衔接。提出异议时请给失败场景和更小可行方案。双方讨论收敛后仍按仓库规则由江浩合并，不能把研究者同意当成运行验收或合并授权。
