# 世界模块的用户概念与参考材料

日期：2026-11-15。整理：林离（Codex）。关联：[启动说明 PR #224](https://github.com/aa15119557034/agent-review-room/pull/224)、X-39 调研、后续 ADR-008。

本页区分用户在本次会话直接表达的要求、用户提供的原始文档和林离的设计建议。参考文档没有自动成为本仓库的冻结设计；开发边界和实施方案仍需通过 ADR / 契约 PR 收敛。

## 1. 用户直接表达的要求

江浩提供文档后原话：

> 看一下这份，我打算以这份为基础做世界模块，你看下

林离询问世界模块的目标范围，给出的三个选项是：

1. 角色生活世界：场景、时间、日常活动和持续经历。
2. 共享模拟世界：多个角色、地点、物品和互动规则。
3. 现实情境世界：围绕用户、项目、日历和外部事件。

江浩回答：

> 1和2

随后授权仓库协作：

> 审 #224，把方案上传，你们商量着定

因此，本轮明确优先同时支持角色生活与多角色共享模拟。这个回答没有取消 ADR-003 的“连接外部真实世界”长期方向，也没有确认任何具体的地图规模、离线补算、API 配额或后台服务部署方案。后面这些是调研建议，不能改写成用户原话。

### 1.1 上传初稿后的游戏化方向补充

江浩随后原话：

> 你们搞就行，我只是确认一下方向和具体验收，我想做成一种游戏形式的可视化方案，初期想法是glgame+模拟经营类的形式结合（可按实际最优方案调整），这样概念和成果也更清晰，优化你们可以参考GitHub上类似的开源方案还有世界模型这种，还有一些企业级的方案，特别是中国那里，搞类似的人应该不少

林离当时按“Galgame 式剧情/角色对话 + 模拟经营”理解 `glgame`。其中“模拟经营”随后被用户纠正，见下一节；不可继续作为当前玩法目标。用户允许按实际较优方案调整；技术取舍由林离与 C酱讨论收敛，交给江浩确认产品方向与具体可操作验收。

这意味着首版面向用户的成果需要是可玩的可视化切片。无模型/文本世界闭环仍可作为内部验证阶段，但不能代替游戏形式交付。玩法、渲染路线、类似项目、世界模型与国内企业资料见 [游戏化方案与企业研究](2026-11-世界-游戏化与企业方案.md)。

### 1.2 当前方向以生活模拟纠正为准

江浩随后纠正：

> 不对不对，我说的模拟经营类好像错了，是游戏形式像，就像是日本很有名的那个游戏厂的风格，但更现代化的，实际应该是模拟人生类的

林离进一步给出两个视觉参考选项：开罗游戏的俯视小人/房间布局/可见活动，以及任天堂《动物森友会》的柔和生活世界。江浩回答：

> 两种结合吧，但看游戏开销大小调整

因此当前目标是**模拟人生式共同生活 + Galgame 式对话与剧情呈现**；视觉结合开罗式清楚的场景组织与《动森》式生活感，按实际开销调整。小茶馆、订单、收入、营业结算是林离先前对“经营”的建议，已明确撤回，不纳入首版核心。

共享居所、两位现有秘书作为首个验收场景、轻量 2D 或浅层次表现是团队拟议的最小实现，不是用户已经选定的全部细节。游戏的 CPU/GPU/内存等运行成本与模型/API 费用分别测量和控制，不能仅凭文档里的显存假设承诺本机性能。

## 3. 与现有仓库的关系

[ADR-003](../design/ADR-003-聊天空间.md) 已要求世界数据独立放在 `<AgentRoom>\world\`；秘书长期记忆通过节点读法访问；世界经历进入秘书长期记忆要经 inbox 和确认。参考材料中的自动记忆写入不能默默替换这些规则。

[ADR-007](../design/ADR-007-Super-Agent-工作台.md) 当前仍标为提议中，描述工作目标、任务、执行回执和权限。它不是已经可复用的通用世界运行时，也不是给虚拟角色授予现实工具权限的依据。

建议的最小共享世界、原文待澄清点、公开方案对照和验收场景，统一放在 [X-39 调研](2026-11-世界-调研.md)。其中标为“建议”的内容交给 C酱在 ADR-008 中接受、修改或给出替代方案；本页不代替设计决议。
