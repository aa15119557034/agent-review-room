# 把 Python + 语音模型打进安装包

> D-39b 之后的打包工作（汐）。目标是「装完之后开箱就能用语音合成」，不再依赖本机的 `E:\AI\TTS`。

## 打进去的是什么

| 资源 | 来源（默认） | 装到哪 |
|---|---|---|
| base Python 3.11 | `E:\AI\TTS\pythons\cpython-3.11.13-windows-x86_64-none` | `<resources>/tts/python` |
| 第三方依赖（torch 等） | `E:\AI\TTS\index-tts\.venv\Lib\site-packages` | `<resources>/tts/site-packages` |
| IndexTTS2 代码 | `E:\AI\TTS\index-tts`（不含 `.venv`） | `<resources>/tts/index-tts` |
| 模型权重 | `E:\AI\TTS\models\IndexTTS-2` | `<resources>/tts/models/IndexTTS-2` |
| 独立进程脚本 | 仓库 `apps/desktop/tts/runner.py` | `<resources>/tts/runner.py` |

合计约 **18 GB**（torch 依赖 7.35 GB + 模型 10.6 GB + Python 0.07 GB）。

源目录可以用 `TTS_BUNDLE_DIR` 覆盖（默认 `E:\AI\TTS`）。

## 怎么打

```powershell
# 只出免安装目录，验证布局（快）
pnpm --filter @room/desktop run pack:dir

# 完整 NSIS 安装包（约 18GB，慢）
pnpm --filter @room/desktop run pack
```

产物在仓库根目录的 `release/` 下（`win-unpacked/` 或 `*.exe`）。

脚本（`apps/desktop/scripts/pack.mjs`）会：
1. 检查四样资源都在，缺哪个就报哪个；
2. `electron-vite build` 出 `out/`；
3. 用 `electron-builder` 打包，`extraResources` 把上面四样拷进 `resources/tts`。

**不需要 electron-rebuild**：better-sqlite3 v13 用的是 Node-API 的 prebuilds（`prebuilds/win32-x64`），Electron 直接能加载；`electron-builder.yml` 里 `npmRebuild: false`。

## 运行时怎么找

`apps/desktop/src/main/tts-paths.ts`：安装包模式（`app.isPackaged`）下检查 `<resources>/tts` 里五项都在 → 用包里的 Python / 脚本 / 模型 / 代码 / site-packages。

- 用 **base Python + `PYTHONPATH` 指到自带 site-packages**，不用 venv 的 `Scripts/python.exe`（它靠 `pyvenv.cfg` 里的绝对 home，换机器就断）。
- `userData/tts.json` 仍然优先：如果它的 `python` / `script` 存在，就用用户的配置（开发机 / 高级用户）。
- 用户配置里的 `voices`（参考录音）会合并进自带配置；模型本身不带音色，第一次用需要在设置里选 / 放一段参考录音。

## 已知限制

- 安装包会非常大（~18GB），NSIS 打这么久主要花在压缩上；`--dir` 快很多。
- 打包机需要足够磁盘；本机测试时 `release/` 会再占一份 ~18GB。
- 真机首次合成要加载 10.6GB 模型，按 `tts.ts` 的 `loadTimeoutMs`（默认 120 秒）算。
