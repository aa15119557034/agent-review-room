# X-45：3D 切片验证与复现

本片是 [#241](https://github.com/aa15119557034/agent-review-room/issues/241) 的首个真实建模切片；真实后台的独立 GUI 验收由林离进行。这里的固定 fixture 只证明渲染、布局与本地交互代码，不证明真实节点、模型、世界存档或全部十项体验通过。

## 运行与验证

标准安装后的命令：

```text
pnpm --filter @room/desktop build
pnpm --filter @room/desktop start
node node_modules/typescript/bin/tsc -p apps/desktop/tsconfig.json --noEmit
node node_modules/typescript/bin/tsc -p apps/desktop/src/renderer/tsconfig.json --noEmit
node node_modules/typescript/bin/tsc -p apps/desktop/e2e/fixtures/tsconfig.world3d.json --noEmit
node node_modules/tsx/dist/cli.mjs --test apps/desktop/src/renderer/test/world.test.ts apps/desktop/src/renderer/test/world-3d.test.ts
node scripts/verify-world-3d.cjs <输出目录> <现有可启动的electron.exe>
node scripts/verify-world-3d.cjs <另一个输出目录> <现有可启动的electron.exe> --low-dpr
```

渲染入口会构建独立 fixture、显示自己的校准窗口 30 秒，记录实际 GPU、窗口内尺寸、DPR、rAF P50/P95/FPS、draw calls、三角形与几何/纹理数，保存全景/近景/960×760 外窗截图后关闭。它不操控用户其他窗口，不调用真实模型或写用户资料；不自动安装、升级任何依赖。断言包括四位居民、唯一一本书、120 字闲聊 + 497 字事实 + 规则旁白均保留、文本可滚到末尾、选项/输入仍在舞台内，以及该机固定场景达到 30 FPS。

本机复用的依赖以**独立工作树内逐个 junction** 指向既有只读包；新 `three` 与 `@types/three` 固定 `0.187.0`，实际安装在本任务专属前缀后只链接这两个包。没有在共享 `E:` 的 `node_modules` 执行安装。`pnpm install --lockfile-only --ignore-scripts --no-frozen-lockfile` 只增加这两项和类型包自带传递依赖，既有锁定版本未变。junction 没有生成 `.bin`，所以本机实际构建使用 `apps/desktop` 目录中的 `node node_modules/electron-vite/bin/electron-vite.js build`，输出成功；这与正常安装后上面的 build 脚本相同。

## 验收关注点与未覆盖

- 四位新居民 + 玩家、旧八居民 + 玩家的公共房间位置不重叠；混合活动发生展示冲突时只分配显示槽位，不改地点/活动。唯一炉灶优先留给活动的第一位厨师。
- 收到暂停快照时直接对齐已提交的地点/活动目标并清除途中插值，避免世界状态说“已在厨房”而画面永远停在走廊。
- scene 先于 GLB 载入时，素材就绪后仍触发近景；换局/名单重建清旧错误与旧标签。每个成功 GLTF 单独登记所有权；局部失败/取消/迟到成功都释放，克隆共享模板资源直到场景卸载，再统一释放几何、材质、纹理和去重后的 ImageBitmap。
- 唯一小说与锅各只有一个模型，来源是 `world.items.at/usedBy`；厨房食材/饭数量来自快照。没有从台词生成物品或动作。
- 人物仍是基础模型加发色/衣服区分；没有个性化脸型、完整专属动画、口型、手指握持、布料或物理碰撞。路线是有限锚点的本地插值，复杂多人交错仍须真实 GUI 复核。整理/摆桌暂无专属完整动作。
- 真实模型/节点、完整跨日生活、强杀恢复、真实后台开销和最终人物美术风格不能由这些截图或 fixture 声称已验收。
