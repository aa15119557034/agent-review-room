## 3. 契约是唯一的接口

前后端、Orchestrator 和远端节点、以及以后的手机 App，都只通过契约对接：

| 文件 | 内容 |
|---|---|
| `schemas/src/state-machines.ts` | Approval / Run 的合法转换表（数据，不是 if） |
| `schemas/src/agent-event.ts` | Orchestrator 内部统一事件 |
| `schemas/src/remote-protocol.ts` | Orchestrator ⇄ AgentServer |
| `schemas/src/control-api.ts` | 人 ⇄ Orchestrator（桌面 renderer 和以后的手机 App 共用） |
| `core/src/adapter/*.ts` | AgentAdapter / RemoteAgentAdapter 接口 |

契约变更流程：提 PR 改契约 → 你批准合并 → 双方各自适配。契约 PR 里不能夹带实现代码。

## 4. 交叉审查

- Claude 写的 → DeepSeek 审：找反例、补测试；契约另请 Codex 看一遍
- Codex 写的 → DeepSeek 审实现、Claude 审和契约是否一致
- DeepSeek 写的状态机 / DB / 进程 / 网络 → Claude 审
- **写代码的会话不审自己的产出。** Claude 审查时开新会话，只给它 PR diff 和契约
- 审查意见写在 PR 评论里，审查方**不直接改**被审代码

## 5. 与 V0.4 的偏离（有意的）

1. **Claude 有两个身份。** 执行者身份写 UI 和契约；Reviewer 身份只读，问题写成评论交回所有者。
2. **Phase 0 没有 worktree 自动化。** 用 git 分支 + PR 隔离。
3. **远端执行节点（ADR-001）。** 契约现在定，实现放 Phase 1，不阻塞 Phase 0。

## 6. GitHub 协作流程

仓库：`aa15119557034/agent-review-room`（私有）

```
main（受保护，只有你合并）
 ├─ claude/C-01-contract        ← Claude 推送，开 PR
 ├─ deepseek/D-01-scaffold      ← DeepSeek 推送，开 PR
 ├─ codex/X-20-prompt           ← Codex 推送，开 PR
 └─ ...
```

每个任务：

1. `git switch main && git pull --rebase`
2. `git switch -c <名字>/<任务ID>-简述`
3. 小步提交，commit 前缀 `[<名字>] <任务ID>`，例如 `[deepseek] D-02 add migrations`、`[codex] X-20 history compression`
4. 推送并开 PR，PR 描述用 `.github/pull_request_template.md`
5. 对方审查 → 你合并 → 删除分支

PR 里写"测试通过"必须贴实际命令和输出，否则视为 claimed。

绝不提交 `.env`、API key、token、`*.db`、`agent-server.config.json`。
