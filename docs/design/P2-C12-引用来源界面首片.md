# P2-C12 首片：引用展示、来源预览 mock 与旧批准失效提示

林离实现，C酱评审。按 [#259 合并后分工](https://github.com/aa15119557034/agent-review-room/pull/259#issuecomment-6926178061) 的 renderer 目录例外推进；先 mock，使用已合并 P2-C11 的 `SourceReference` / `ResultDisplayBlock`，不改 schemas、main、DB 或新增 IPC。

## 已实现的界面

- `SourceReferences` 展示来源身份、完整版本、正文 SHA-256、记录时间，以及 readable / missing / revoked。状态明确写成“记录时”，不会把旧状态当成当前授权。未知版本/hash 不补默认值。
- 原文卡片、单次评审批准页、结果/已发送 Prompt、讨论室逐人批准页读取既有 Message / Snapshot 的可选 `sourceRefs`。旧数据没有这个字段时不多显示空卡片。
- 引用标题、工具名称/简述、未知展示类型、原文都用文本节点，不能解析 HTML、Markdown 或自动链接。来源网址只作文字；本片没有系统浏览器打开命令，也不自动访问或预取网页。
- `ResultDisplayView` 为已经投影的展示块提供视图：工具步骤标成运行方报告，不改变 Run 最终状态；累计用量中的未知、实测 0 和小额费用保持区别。**展示事件查询尚未开放，真实流未接线**。
- `?mock&sources` 可交互演示来源可读、缺件和撤回；切换为缺件/撤回时移除原文，保留旧引用和当前模拟检查的区别。只在浏览器 mock 启用，Electron 的真实 bridge 优先，URL 参数不能把真实应用切到 mock。

## stale_snapshot 后必须重建

单次批准与批量盖章沿用 D08 的 `stale_snapshot` 错误码。收到后保留旧 Snapshot/审批记录，显示“更新资料并重新生成预览”，停用旧审批发送。批次关闭后重开仍保留重建提示；“退回去重建”走既有 `batch.reject`，初始轮的任务回到输入框，再按原有 `round.redraft` 生成新预览，不自动批准。

这只是本次界面的错误恢复状态，不持久化、不改后端业务状态，也不替代 main 每次批准时的来源检查。切换项目会清理这部分 UI 状态；重启后仍由 main 校验旧批准。其他失败不会自动当成来源失效。

## 接真还缺的契约

1. main 按当前数据库/项目和来源版本提供只读预览，重新检查归属、撤回、hash；不能直接从历史 `sourceRefs` 或缓存正文推导可读性。
2. S07 项目检索的批准命令，以及完整正文/原件/展示事件的提交顺序；其生产端见 [#260](https://github.com/aa15119557034/agent-review-room/pull/260)。当前只有可选来源记录的展示，没有桌面搜索入口。
3. 跨秘书分享继续绑定同一个授权原件和版本；本片不新增分享写入命令，也不把 renderer 提交的 URL/hash 当成可信原件。

上述部分需小契约先合并，再接 main。聊天网页来源、文档上传/解析、重启后的真实投影重放和完整 P2-X12 仍未验证。本片没有宣称完整“搜索→桌面共享→多秘书引用”链路已上线。
