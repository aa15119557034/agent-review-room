## 背景

江浩 2026-11-15 定了三件事：

1. 以《Cognitive Backend V0.4.1》为基础做世界模块。
2. 方向选「角色生活世界」和「多角色共享模拟世界」。连接现实世界（日历、外部事件）没有取消，放到后面。
3. 要做成**游戏形式的可视化**，「这样概念和成果也更清晰」。他先说的是 galgame + 模拟经营，随后纠正：「我说的模拟经营类好像错了，是游戏形式像……实际应该是模拟人生类的」，画面感觉像「日本很有名的那个游戏厂的风格，但更现代化」；在开罗式俯视小人房间和任天堂式生活世界之间，他说「两种结合吧，但看游戏开销大小调整」。所以玩法是**模拟人生式的共同生活 + galgame 式的对话和剧情**，不做经营赚钱。画面取开罗式清楚的房间和小人、加上温暖的生活氛围，用自己的美术，不写死像素还是 3D，复杂度看实际开销调。技术取舍由 C酱 和林离定，他看产品方向和具体验收。

原文是一整套长期架构，假设有一个已经存在的 V0.3 运行时，本仓库没有。第一版取原文最底下那一层当地基，上面直接做成能玩的东西：

> 代码维持世界，状态维持主体……事实与身份的最终写权始终留在本地受控层。（原文 §25）

## 给江浩看的：第一版是什么，怎么验收

**是什么**：秘书们住在一间小屋里过日子，像模拟人生。她们有自己的作息，会自己去做饭、吃饭、看书、休息、找对方说话，会累、会饿、心情会变。你也在这个家里：能看着她们生活，也能走到某个房间、找她说话、邀她一起做事。有事发生或者你找她说话时，画面切成 galgame 那样：背景、立绘、对话框，有时有选项。你做的事会留下后果，第二天她们还记得。

没有赚钱、订单、营业额这些经营目标。

**你能动手做的验收**（做完第一版后，你照着点一遍。和林离在 #226 调研里列的是同一套）：

1. 点导航里的「世界」，进到家里，看到几个房间、住在里面的秘书、屋里的东西。
2. 什么都不做，看一会儿：她们按自己的作息和兴趣在走动、做事、换事情做，不用你一件件下命令。
3. 走到一位正在做事的秘书旁边和她说话：出现她的立绘和对话框，她知道自己正在做什么。说完回到总览，她的位置、手里的东西、事情的进度都对得上。
4. 邀一位正忙着的秘书一起看书或摆餐桌：她答应、说晚点、或者说来不了。答应了就真的走过来一起做；说晚点的，之后真的有下文。
5. 两个人都想用同一本书或同一个座位：有先有后，后来的等、商量、或者去做别的，东西不会同时在两个人手里。
6. 饭没做好时问她，她说的是真实进度；做好了才多出几份饭；一起吃完，饭少了对应的份数，之后聊天会提到这顿饭。
7. A 趁 B 不在把书挪了地方，再分别问她们：A 知道在哪；B 只知道原来的位置或者说不知道，有人告诉她以后她才知道。
8. 做到一半或等她回应时按暂停、关掉程序再打开：回到原来的状态，时间从关掉的地方接着走，饭不会多做一份，取消了的邀约不会又被执行，也没有凭空多出「你不在时发生的事」。之前的对话可以回看。
9. 过到第二天：昨天她亲身经历的事和没完成的约定能接上；她没参与的事她不知道。
10. 把一位秘书的节点关掉：世界照样在过，她按平常的作息生活，台词变成简短旁白，界面上写明她现在不在线。

## 决定

### 1. 玩法：一起生活

- **地点**：客厅、厨房，和每位居民自己的房间。只有「哪间连哪间」，不做坐标和物理。
- **居民**：现有的秘书，复用秘书页的名字、人设和各自的节点，不另造角色。规则不写死人数；第一版验收用两位。
- **居民的状态**：体力、饱腹、心情三个数，随时间和做的事变化，由规则算。每人有一份默认作息（几点起、几点吃、几点睡）。
- **两个人之间**：一个「熟悉度」，有方向（A 对 B 和 B 对 A 分开），由规则按一起做过的事、说过的话来加减，模型不能直接改它。它只用来影响规则判断（比如更愿意答应邀约），**界面上不显示成分数**，不做成可以刷的东西，也不做好感度剧情线。
- **约定**：谁答应了谁什么、什么时候、现在是待办、完成、推迟还是取消。答应了的事到点会有下文。
- **屋里的东西**：少量。至少一样是唯一的（一本书、一个座位），食材和做好的饭记数量。缺食材时做不了饭，不会凭台词变出东西。
- **居民能做的事**：走到隔壁、拿起、放下、休息或睡觉、做饭（要花时间、占着锅、消耗食材）、吃饭、看书、对同屋的人说话。
- **居民自己怎么过**：到点按作息；空档里由模型按她的状态和眼前的情况提议做什么；模型不在就按作息和简单规则（饿了去吃、累了去睡）。
- **江浩能做的事**：
  - 江浩自己也在世界里，有所在的房间。点地点走过去，点人和东西来互动，不用键盘操纵。
  - 邀某位居民做某件事或一起做。这是一个「请求」：她可以答应、推迟或拒绝；规则检查做不做得了（东西被占着就做不了）。答应和完成分开显示，不能只在台词里「做了」。
  - 走过去和某位居民说话（见第 2 节）。
  - 在剧情里选选项。
  - 暂停、继续、重置；切到某位居民的视角看「她知道什么」。
  - 江浩的每个操作也是一条动作，和居民的动作走同一套检查。
- **一天的回顾**：每天结束时，按当天的事件整理出一份回顾（谁做了什么、发生了什么）。内容来自事件记录，模型只润色措辞。
- 没有钱、订单、营业结算。

### 2. 剧情和对话（galgame 的部分）

- **样子**：背景 + 在场居民的立绘 + 对话框 + 有时有选项。
- **两种触发**：
  - **自己冒出来的**：规则层判定「这件事值得一段剧情」时触发。第一版固定几种：两人争同一样东西、做饭成功或失败、有人太累太饿或心情太低、两人第一次一起做某件事、一天结束的回顾。
  - **江浩找她说话**：走到她所在的房间开始对话。可以选给出的选项，也可以打一句话。
- **选项是什么**：每个选项对应一个规则层认可的动作（「让 A 先看书」「劝 B 去休息」「不管，看她们自己商量」）。选了以后走第 5 节的动作流程，结果回写世界。选项由规则给出，模型不能发明新选项。
- 选项过期了（情况已经变了）要明确失效或重新给，连点两次不会做两次。
- 打开对话不会偷偷暂停世界；想停下来慢慢看就自己按暂停。
- 对话可以回看。回看只是重放显示，不改世界。
- **打一句话**：她的回应是台词；如果你的话是让她做什么，她的模型可以据此提议一个动作，照样要过规则检查。说了什么会记成在场居民的观察。
- **台词**：模型写。它拿到的是这位居民视野里的事和这一场的情况，回的是受限的显示内容（谁说、说什么、哪个表情），程序不执行模型给的任何脚本或代码。
- **模型不在**：自己冒出来的剧情用规则生成的简短旁白，选项照常；找她说话时明说她现在没法回应。世界照样能过。
- 每段场景的模型调用次数有上限（见第 8 节）。江浩主动找她说话优先于她们自己的认知请求。

### 3. 画面怎么做

- **不嵌第二个游戏引擎**（Ren'Py、Godot、Unity）。在现有 Electron 界面里做：剧情场景和状态面板用现有的 React 和 CSS。
- 画风：轻量 2D，俯视或房间切面，清楚的房间和小人加上柔和的生活感；用自己的美术，不照搬任何游戏的角色和素材。小屋视图里的走动动画，先用 CSS 试；不够再引一个轻量 2D 画布库（优先看 PixiJS，许可和体积合适再用）。引库不是第一版的前提。
- 可以借鉴 WebGAL 的交互方式，不整体搬它的引擎和存档体系。
- **世界模型（生成画面或视频的那类）不负责记账**：库存、位置、谁看到了什么、钱，一律以规则层为准。以后最多用它出过场画面，第一版不碰。

### 4. 美术

- 立绘、表情、背景用本机 ComfyUI（ADR-004 已有的画图通道）事先生成，存成固定素材反复用，不在每句台词时现画。第一版每位居民少量几张表情。
- 没装 ComfyUI：用随程序带的、许可清楚的占位素材，世界照样能玩。
- 画图失败不影响世界进度；画图的花费和世界认知的次数分开算。

### 5. 谁能改世界，动作怎么生效

| 层 | 第一版 | 能做 | 不能做 |
|---|---|---|---|
| 规则层（程序） | 做 | 推进时间、判定动作成不成、结算活动、算状态和熟悉度、写事件、决定出不出剧情 | — |
| 认知层（节点上的模型） | 做，受限 | 看自己视野里的事，**提议**一个动作，写台词 | 直接改位置、物品、状态数值、熟悉度、活动结果、时间；发明选项 |
| 常驻小模型、二次判断、评价、学习（原文 §8、§10、§18、§19） | 不做 | — | — |

```
提议（居民的模型、江浩的操作、作息规则）→ 检查 → 接受 →（耗时的进入「活动」）→ 结果 → 写事件和观察
```

- 世界只有一个写入口，一次处理一个动作。检查、改状态、写事件、写观察在同一个数据库事务里。
- 每个动作有唯一 ID，同一个 ID 再来一次不重复生效。
- 耗时活动：开始时不产生结果；到时间才结算一次；中途取消按规则释放占用的东西、结算已消耗的材料。
- 迟到的提议（模型回来时活动已取消、东西已被拿走、世界已暂停或恢复过备份）：按最新状态重新检查，不通过就作废，不能让已结束的活动复活。
- 随机：第一版不加随机事件。以后加时，抽到的结果随事件一起存，恢复时读存下的结果，不重抽（修正原文 §5.2 和 §36 第 11 条的冲突：世界规则可以有可审计的随机，表达上的随机不改事实）。

### 6. 世界里有什么数据

| 对象 | 记什么 |
|---|---|
| 世界 | 身份、世界时间、第几天、规则版本、运行或暂停、事件序号 |
| 地点 | 稳定 ID、和哪些地点相连 |
| 居民 | 是哪位秘书、在哪、当前活动（最多一个主要活动）、体力、饱腹、心情、作息 |
| 熟悉度 | 谁对谁、数值、由哪些事件改的 |
| 约定 | 谁和谁、约了什么、期限、状态 |
| 江浩 | 在哪个房间 |
| 物品和库存 | 稳定 ID；唯一物品有唯一的所在（某个地点**或**某位居民手里）；消耗品记数量 |
| 活动 | 谁、占着什么、什么时候开始、预计什么时候结束、状态、为什么结束 |
| 事件 | 序号、世界时间、谁做了什么、结果、规则版本。只追加，不改 |
| 观察 | 哪位居民、看到或听到了什么、什么时候、是亲眼看到还是听人说 |
| 剧情场景 | 由哪个事件触发或是江浩发起、给了哪些选项、江浩选了什么或说了什么、显示过的台词 |

「听人说」和「真的发生了」分开记。B 听 A 说冰箱里还有菜，只记成 B 的一条观察，不改食材的真实数量（原文 §5.3、§36 第 2 条）。

类型名和字段在契约 PR 里定，本文只定语义。

### 7. 每位居民只知道自己看到的；时间怎么走

**视野**：世界有一份完整的真实状态，但居民拿到的只有自己的观察：同一个区域里发生的事她能看到，别处的不能。给模型的上下文、摘要、以后任何检索和回查，都只能从这位居民自己的观察里取。江浩的全貌视角只在界面上，不进任何居民的上下文。

**时间**：

- 程序开着时，世界时间往前走（世界里的一天对应现实里多久，是可调的参数，默认值在契约 PR 里定，要让一天能在一次坐下来的时间里过完；睡觉这种长活动可以快进）。江浩不操作也照走，不需要模型在线。
- **暂停的三种情况**：江浩按了暂停；程序退出；电脑休眠。暂停时世界时间不走，活动冻结。窗口最小化不算退出。
- 恢复后从停下的地方接着走，**不补算**停掉的那段时间，不编造经历。
- 系统时间被改或跳变时不跟着跳：每一步只按单调时钟的实际间隔推进，间隔异常大就当成暂停过。
- 重启恢复：读已提交的状态和事件，不重新问模型，不重复结算。
- 程序关掉后继续运行（24 小时不停）需要另做常驻后台，以后另开 ADR。

### 8. 什么时候叫模型，花多少

- 规则推进不花模型调用。只在这些时候叫：居民要决定空档里做什么、有人对她说话、出剧情场景要台词、润色一天的回顾。
- 全世界同一时间最多一个认知请求。**聊天和讨论室优先**：她正在聊天或讨论室里干活时，世界的请求往后排，不抢节点。
- 一段场景的台词轮数有上限；居民之间的对话有轮数上限和冷却，不会互相无限触发。
- **每日上限**：每位居民每天的认知次数有上限，设置页可调。订阅节点报不出金额，所以只承诺「次数上限」，不承诺「金额上限」。
- **用完了或节点不在线**：世界照常走；居民按作息和简单规则生活；台词换成规则旁白；过期的请求不排队，恢复后不补跑；界面上明说原因。
- 复用现有的文本 Run 通道，只读、不给任何工具权限。模型回的内容按固定格式解析，解析不了就当作这次没有提议或没有台词。

### 9. 和记忆的边界

沿用 ADR-003 的规矩，说清三种东西：

1. **世界记录**（状态、事件、观察、场景）：自动保存，用来恢复和回看。
2. **世界内回忆**：居民自己的观察记录（含每天的回顾里她在场的部分），自动带进她**在世界里**的认知上下文，标明是「世界内经历」和属于哪个世界，受视野限制。带多少、多久以前的怎么压缩，在契约里定上限。验收里「第二天问她昨天的事答得上来」靠的是这一条。
3. **个人长期记忆**（节点上的 `memory\`）：世界经历要进这里，必须先成候选、进 inbox、江浩确认。第一版这条路不做（inbox 的提交和确认界面都还没有），只留候选记录的位置，不做半截。

聊天和讨论室的上下文第一版不带世界经历。以后要让秘书在聊天里聊起小屋的事，先做第 3 条那套确认，再另行决定。世界里发生的事不能被说成现实里发生过。

### 10. 存在哪，谁来写，怎么备份

**世界数据放进现有的 `room.db`，由桌面 main 进程写。**

- main 进程已经是数据库唯一的写入者，有单实例锁。事务、数据库版本升级、备份和恢复（ADR-006）沿用现有的。
- 这**修订了 ADR-003「世界自己的数据放 `<AgentRoom>\world\`」那一条的字面**。那条的本意是不和 `memory\` 混放，仍然满足。`world\` 目录留给以后有明确引用的素材或导出。
- 世界在跑时备份：先自动暂停，备份完只恢复「是这次备份暂停的、并且江浩这期间没有自己按过暂停或继续」的世界；本来就暂停的不会被启动。备份失败也要回到备份前的状态，不能不明不白停着。
- 从备份恢复后，恢复之前发出去的模型请求回来一律作废。
- 素材：随程序带的默认素材不用备份。ComfyUI 生成的素材要么走现有的附件存放（备份已覆盖），要么把备份清单、复制、校验、恢复一起扩上，二选一在契约里定，不能丢。
- **备份时的顺序**：先关掉世界的入口（不再接新动作、迟到的模型结果作废）→ 等已经接下的写入做完 → 再备份。不能占着写入队列等队列自己排空。
- **换资料文件夹、退出、从备份切换**：先停世界、把旧的模型回调隔开，再开新库；切换成功后不能把旧世界恢复起来。一个数据库同一时间只有一个世界在跑。
- 世界记录进了整库备份，不等于进了资料搜索和分享导出。第一版只保证完整备份恢复，世界历史的搜索和分享放后面。

### 11. 和 ADR-007、和现实世界的关系

- 世界里的「活动」只管虚拟居民。ADR-007 的目标和任务管现实里的成果。世界里「写了一封信」不等于现实里发了邮件。
- 第一版不依赖 ADR-007，也不做第二套通用任务调度。
- 现实来源（日历、天气）和现实动作（发消息、控制设备）都后置。以后接时先接一种只读来源；现实动作要等节点的授权和回执能力做好，世界不能自己去碰外部工具。

## 验收

两层，互相不代替。

**给江浩的**：上面「你能动手做的验收」10 条。

**内部的（林离做，规则居民不调模型，结果可重复）**：以 X-39 调研第 8 节的表为准（争用唯一物品、耗时活动与中断、秘密移动、告知与真值、迟到认知、暂停再恢复、提交故障、停机与时间变化、节点与预算故障、个人记忆、现实副作用、来源与范围），再加：

- 世界在跑时备份：按第 10 节的规则暂停和恢复；从备份恢复后状态和事件完整，旧的模型结果进不来。
- 数值可追溯：体力、饱腹、心情、熟悉度、约定状态和物品数量都能从事件记录重新算出来，和显示的一致。
- 换资料文件夹和退出：旧世界的模型结果进不了新库。
- 江浩的操作：让她做事、选选项、说的话，每一次都留下一条动作和结果；重启后不会重复生效。
- 回顾不编造：一天的回顾里每一条都对得上事件记录；某位居民回忆时说不出她不在场的事。

模型接入后另看台词和行为是否自然，这个靠真跑、靠江浩看，不靠自动打分。
