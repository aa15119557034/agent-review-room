## 背景

江浩 2026-11-15 定了三件事：

1. 以《Cognitive Backend V0.4.1》为基础做世界模块。
2. 方向选「角色生活世界」和「多角色共享模拟世界」。连接现实世界（日历、外部事件）没有取消，放到后面。
3. 要做成**游戏形式的可视化**：「初期想法是 galgame + 模拟经营类的形式结合（可按实际最优方案调整），这样概念和成果也更清晰」。技术取舍由 C酱 和林离定，他看产品方向和具体验收。

原文是一整套长期架构，假设有一个已经存在的 V0.3 运行时，本仓库没有。第一版取原文最底下那一层当地基，上面直接做成能玩的东西：

> 代码维持世界，状态维持主体……事实与身份的最终写权始终留在本地受控层。（原文 §25）

## 给江浩看的：第一版是什么，怎么验收

**是什么**：秘书们住的小屋里有一个小茶馆。你每天早上给她们分工，她们自己去做；有事发生时会出一段像 galgame 一样的剧情，你可以只看，也可以选一个选项插手；晚上结算，看到今天卖了几单、茶叶还剩多少、赚了多少、每个人累不累开不开心。第二天接着过。

小茶馆只是第一版的题材，为的是让「分工、做事、出剧情、算账」这一圈能转起来。不喜欢这个题材可以换，规则不用重做。

**你能动手做的验收**（做完第一版后，你照着点一遍）：

1. 点导航里的「世界」，看到小屋的三个区域、住在里面的秘书、茶壶和茶叶这些东西。
2. 给两位秘书排今天的事（谁泡茶、谁招呼客人、谁休息），按「开始这一天」。
3. 看到她们走动、做事，头像或立绘在对应的区域里，进度在走。
4. 至少遇到一段带选项的剧情（比如两个人都要用那把唯一的茶壶）。选一个选项，看到结果真的变了。
5. 一天结束，看到结算：完成几单、茶叶剩多少、收入多少、每个人的体力和心情。用收入补一次茶叶。
6. 关掉程序再打开，进度还在，时间从关掉的地方接着走，没有凭空多出「你不在时发生的事」。
7. 把一位秘书的节点关掉再过一天：世界照样能玩，她按默认作息做事，台词变成简短旁白，界面上写明她现在不在线。
8. 按暂停，世界停住；按继续，接着走。

## 决定

### 1. 玩法：一天一圈

```
早上分工 → 白天她们做事 → 有事时出剧情（可选介入）→ 晚上结算 → 第二天
```

- **地点**：三个连着的区域（比如茶座、后厨、休息间）。只有「哪里连哪里」，不做坐标和物理。
- **居民**：现有的秘书，复用秘书页的名字、人设和各自的节点，不另造角色。规则不写死人数；第一版验收用两位。
- **东西和资源**：一种茶、一把唯一的茶壶、有限的茶叶、当天的两笔订单、虚拟的钱；每位居民有体力和心情。
- **能做的事**：走到隔壁、拿起、放下、休息、泡茶（要花时间、占着茶壶、消耗茶叶）、招呼客人交付订单、对同屋的人说话。
- **江浩能做的事**：早上分工；剧情里选选项；用收入补货；暂停、继续、重置；切到某位居民的视角看「她知道什么」。江浩的每个操作也是一条动作，和居民的动作走同一套检查。
- **结算**：订单完成数、材料消耗、收入、体力心情变化，全部由规则算，模型不参与算账。

### 2. 剧情场景（galgame 的部分）

- **什么时候出**：规则层判定「这件事值得一段剧情」时触发，第一版固定几种：两人争同一样东西、泡茶成功或失败、订单要超时、有人体力或心情太低、一天结束的回顾。
- **样子**：背景 + 在场居民的立绘 + 对话框 + 至多几个选项。
- **选项是什么**：每个选项对应一个规则层认可的动作（「让 A 先用茶壶」「让 B 去休息」「不管，看她们自己商量」）。选了以后走第 5 节的动作流程，结果回写世界。选项由规则给出，模型不能发明新选项。
- **台词**：模型写。它拿到的是这位居民视野里的事和这一场的情况，回的是受限的显示内容（谁说、说什么、哪个表情），程序不执行模型给的任何脚本或代码。
- **模型不在**：用规则生成的简短旁白代替台词，选项照常，照样能玩。
- 每段场景的模型调用次数有上限（见第 8 节）。

### 3. 画面怎么做

- **不嵌第二个游戏引擎**（Ren'Py、Godot、Unity）。在现有 Electron 界面里做：剧情场景和经营面板用现有的 React 和 CSS。
- 小屋俯视图里的走动动画，先用 CSS 试；不够再引一个轻量 2D 画布库（优先看 PixiJS，许可和体积合适再用）。引库不是第一版的前提。
- 可以借鉴 WebGAL 的交互方式，不整体搬它的引擎和存档体系。
- **世界模型（生成画面或视频的那类）不负责记账**：库存、位置、谁看到了什么、钱，一律以规则层为准。以后最多用它出过场画面，第一版不碰。

### 4. 美术

- 立绘、表情、背景用本机 ComfyUI（ADR-004 已有的画图通道）事先生成，存成固定素材反复用，不在每句台词时现画。第一版每位居民少量几张表情。
- 没装 ComfyUI：用随程序带的、许可清楚的占位素材，世界照样能玩。
- 画图失败不影响世界进度；画图的花费和世界认知的次数分开算。

### 5. 谁能改世界，动作怎么生效

| 层 | 第一版 | 能做 | 不能做 |
|---|---|---|---|
| 规则层（程序） | 做 | 推进时间、判定动作成不成、结算活动和账目、写事件、决定出不出剧情 | — |
| 认知层（节点上的模型） | 做，受限 | 看自己视野里的事，**提议**一个动作，写台词 | 直接改位置、物品、钱、活动结果、时间；发明选项 |
| 常驻小模型、二次判断、评价、学习（原文 §8、§10、§18、§19） | 不做 | — | — |

```
提议（居民的模型、江浩的操作、默认作息）→ 检查 → 接受 →（耗时的进入「活动」）→ 结果 → 写事件和观察
```

- 世界只有一个写入口，一次处理一个动作。检查、改状态、写事件、写观察在同一个数据库事务里。
- 每个动作有唯一 ID，同一个 ID 再来一次不重复生效。
- 耗时活动：开始时不产生结果；到时间才结算一次；中途取消按规则释放占用的东西、结算已消耗的材料。
- 迟到的提议（模型回来时活动已取消、东西已被拿走、世界已暂停或恢复过备份）：按最新状态重新检查，不通过就作废，不能让已结束的活动复活。
- 随机：第一版不加随机事件。以后加时，抽到的结果随事件一起存，恢复时读存下的结果，不重抽（修正原文 §5.2 和 §36 第 11 条的冲突：世界规则可以有可审计的随机，表达上的随机不改事实）。

### 6. 世界里有什么数据

| 对象 | 记什么 |
|---|---|
| 世界 | 身份、世界时间、第几天、规则版本、运行或暂停、事件序号 |
| 地点 | 稳定 ID、和哪些地点相连 |
| 居民 | 是哪位秘书、在哪、当前活动（最多一个主要活动）、体力、心情、今天的分工 |
| 物品和库存 | 稳定 ID；唯一物品有唯一的所在（某个地点**或**某位居民手里）；消耗品记数量 |
| 订单和账 | 订单状态和期限；每一笔收入和支出 |
| 活动 | 谁、占着什么、什么时候开始、预计什么时候结束、状态、为什么结束 |
| 事件 | 序号、世界时间、谁做了什么、结果、规则版本。只追加，不改 |
| 观察 | 哪位居民、看到或听到了什么、什么时候、是亲眼看到还是听人说 |
| 剧情场景 | 由哪个事件触发、给了哪些选项、江浩选了什么、显示过的台词 |

「听人说」和「真的发生了」分开记。B 听 A 说茶叶还有很多，只记成 B 的一条观察，不改茶叶的真实数量（原文 §5.3、§36 第 2 条）。

类型名和字段在契约 PR 里定，本文只定语义。

### 7. 每位居民只知道自己看到的；时间怎么走

**视野**：世界有一份完整的真实状态，但居民拿到的只有自己的观察：同一个区域里发生的事她能看到，别处的不能。给模型的上下文、摘要、以后任何检索和回查，都只能从这位居民自己的观察里取。江浩的全貌视角只在界面上，不进任何居民的上下文。

**时间**：

- 程序开着时，世界时间往前走（世界里的一天对应现实里多久，是可调的参数，默认值在契约 PR 里定，要让一天能在一次坐下来的时间里过完）。江浩不操作也照走，不需要模型在线。
- **暂停的三种情况**：江浩按了暂停；程序退出；电脑休眠。暂停时世界时间不走，活动冻结。窗口最小化不算退出。
- 恢复后从停下的地方接着走，**不补算**停掉的那段时间，不编造经历。
- 系统时间被改或跳变时不跟着跳：每一步只按单调时钟的实际间隔推进，间隔异常大就当成暂停过。
- 重启恢复：读已提交的状态和事件，不重新问模型，不重复结算。
- 程序关掉后继续运行（24 小时不停）需要另做常驻后台，以后另开 ADR。

### 8. 什么时候叫模型，花多少

- 规则推进和算账不花模型调用。只在这些时候叫：居民要决定下一步做什么（分工没覆盖到的空档）、有人对她说话、出剧情场景要台词。
- 全世界同一时间最多一个认知请求。**聊天和讨论室优先**：她正在聊天或讨论室里干活时，世界的请求往后排，不抢节点。
- 一段场景的台词轮数有上限；居民之间的对话有轮数上限和冷却，不会互相无限触发。
- **每日上限**：每位居民每天的认知次数有上限，设置页可调。订阅节点报不出金额，所以只承诺「次数上限」，不承诺「金额上限」。
- **用完了或节点不在线**：世界照常走；居民按早上的分工和默认作息行动；台词换成规则旁白；过期的请求不排队，恢复后不补跑；界面上明说原因。
- 复用现有的文本 Run 通道，只读、不给任何工具权限。模型回的内容按固定格式解析，解析不了就当作这次没有提议或没有台词。

### 9. 和记忆的边界

沿用 ADR-003 的规矩，说清三种东西：

1. **世界记录**（状态、事件、观察、场景）：自动保存，用来恢复和回看。
2. **世界内回忆**：居民自己的观察记录，自动带进她**在世界里**的认知上下文，标明是「世界内经历」和属于哪个世界，受视野限制。
3. **个人长期记忆**（节点上的 `memory\`）：世界经历要进这里，必须先成候选、进 inbox、江浩确认。第一版这条路不做（inbox 的提交和确认界面都还没有），只留候选记录的位置，不做半截。

聊天和讨论室的上下文第一版不带世界经历。以后要让秘书在聊天里聊起小屋的事，先做第 3 条那套确认，再另行决定。世界里发生的事不能被说成现实里发生过。

### 10. 存在哪，谁来写，怎么备份

**世界数据放进现有的 `room.db`，由桌面 main 进程写。**

- main 进程已经是数据库唯一的写入者，有单实例锁。事务、数据库版本升级、备份和恢复（ADR-006）沿用现有的。
- 这**修订了 ADR-003「世界自己的数据放 `<AgentRoom>\world\`」那一条的字面**。那条的本意是不和 `memory\` 混放，仍然满足。`world\` 目录留给以后有明确引用的素材或导出。
- 世界在跑时备份：先自动暂停，备份完只恢复「是这次备份暂停的、并且江浩这期间没有自己按过暂停或继续」的世界；本来就暂停的不会被启动。备份失败也要回到备份前的状态，不能不明不白停着。
- 从备份恢复后，恢复之前发出去的模型请求回来一律作废。
- 立绘和背景素材是文件，备份要一起带上或能重新生成，具体在契约里定。

### 11. 和 ADR-007、和现实世界的关系

- 世界里的「活动」只管虚拟居民。ADR-007 的目标和任务管现实里的成果。世界里「写了一封信」不等于现实里发了邮件。
- 第一版不依赖 ADR-007，也不做第二套通用任务调度。
- 现实来源（日历、天气）和现实动作（发消息、控制设备）都后置。以后接时先接一种只读来源；现实动作要等节点的授权和回执能力做好，世界不能自己去碰外部工具。

## 不做（第一版）

- 大地图、坐标、物理、复杂经济
- 好感度、关系数值、多结局剧情线
- 世界经历进个人记忆、聊天里知道世界的事
- 程序关掉后继续运行
- 任何现实来源和现实动作
- 随机事件
- 本地小模型、图谱、自动学习
- 用世界模型生成画面

## 验收

两层，互相不代替。

**给江浩的**：上面「你能动手做的验收」8 条。

**内部的（林离做，规则居民不调模型，结果可重复）**：以 X-39 调研第 8 节的表为准（争用唯一物品、耗时活动与中断、秘密移动、告知与真值、迟到认知、暂停再恢复、提交故障、停机与时间变化、节点与预算故障、个人记忆、现实副作用、来源与范围），再加：

- 世界在跑时备份：按第 10 节的规则暂停和恢复；从备份恢复后状态、事件、账目完整，旧的模型结果进不来。
- 账目：一天结算的收入、支出、库存能从事件记录重新算出来，和显示的一致。
- 选项：江浩在剧情里选的每个选项都留下一条动作和结果；重启后不会重复生效。

模型接入后另看台词和行为是否自然，这个靠真跑、靠江浩看，不靠自动打分。
