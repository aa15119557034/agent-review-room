# P2-D08：资料引用存储与上下文可见性

林离，2026-11-17。依照已合并的 [#256](https://github.com/aa15119557034/agent-review-room/pull/256) 和 [P2-C11 契约](P2-C11-结构化结果契约.md) 实现，待 C酱评审。任务板明确授权本片修改 main、DB 与 Prompt；本片不修改 schemas。

## 存储边界

- 迁移 v28 基于 main `d3402c3` 的 v27。`messages`、`prompt_snapshots`、`chat_messages`、`chat_snapshots` 各增加一个可空 `source_refs` 字段，引用随原记录在同一事务中写入。旧行仍为 NULL，读取时不补字段；用户聊天不能写引用。
- 引用保持创建时的来源、版本、内容 hash、取得时间和状态；SQL 不允许事后更新。资料版本变化要新增原件与引用，不覆盖旧消息或旧快照。
- 原文仍放在已有 Message/ChatMessage 中。网页原件使用 `source_input`，URL、版本、hash 必须与实际 UTF-8 正文相符。只有 URL 或摘要不能假装已经保存了可读原文；本片不访问网页、不自动下载附件。
- 沿用 `run_events`，增加 chat_run 归属并扩展事件 CHECK。每条事件只能属于一种 Run；旧事件逐字段复制，原有追加写、唯一终态约束保留。没有第二消息库、投影表或通用调度器。

## 结果进入存储

`apps/desktop/src/main/structured-results.ts` 提供以后 P2-S07 接线使用的入口：必须同时有节点能力声明和该次请求开关，且 profile 匹配。入口固定数据库实例、Run 和 Snapshot；远端 `started` 前或 `terminal` 后的展示结果只报诊断，不入库。现有 remote-client 会丢弃 `started`，因此时序检查必须在它映射为内部事件之前调用此入口，不能从内部 `AgentEvent` 猜测。

排队前与真正写入前都检查取消和数据库关闭。已到达、排在终态之前的展示结果可以写入；终态后才到达的丢弃。DB 再检查 Run 状态和聊天回答位当前 attempt。同一个事件重放不增行；改变同一事件正文或复用 citationId 指向不同引用会报错。

`readResultDisplay` 从原事件日志重建展示块：usage 取最后一次累计值，不相加；unknown 保持 unknown。普通 `message_complete` 正文仍完整存储。旧 `runs.events` 查询不混入新展示事件。P2-C12 的展示查询与界面接线尚未实现。

## 可见性与撤回

消息引用限于当前项目；聊天引用限于当前会话，或项目明确选入的 `chat_material` 消息。检查被分享回答的依赖时只验证其原会话内的可见性，不把未选入的私人原文一并分享。

新 Prompt 是派生视图，保留历史记录不变。引入的原文复用 `wrapChatUntrusted`；不可读资料不补造正文。窗口外的聊天来源只留缺件说明，不借引用重新展开旧窗口。没有引用时，Prompt 仍走原先的内容与 hash 路径。

回复和讨论汇总继承输入快照、已存 citation 的来源依赖；这是保守的来源记录，不是“模型已经读过”或“执行已经批准”的证明。`sourceRefs` 仍处于 C11 约定的 contentHash 覆盖范围之外，没有成为新的审批清单。

撤回沿引用关系传播：

1. 后续聊天、讨论历史、未完成发言和摘要排除失效依赖；X-35 相关摘要在撤回事务里标为 stale。
2. 新增 citation 引入的摘要依赖也参与检查，即使它不在摘要原来的 `sourceMessageIds` 中。生成结束时再次检查，迟到的摘要不发布。
3. 方案从已有汇总关联及父版本链派生依赖。失效的方案不能再进入新 Prompt，不修改历史方案结构。
4. 新快照写入、单次/批次批准、暂停恢复、异步会话初始化后的真正发送，以及正式回答落库，都检查来源。撤回与这些步骤交错时，事务回滚或阻止发送。
5. 聊天材料原文丢失时，不回退到旧副本。旧的超长 Prompt 测试改用真实原文，另测缺失来源不进入 Prompt。

网页的外部撤销通知、历史导入、文件上传，以及手写笔记的来源追踪不在本片中；没有增加它们的契约或自动处理入口。
