# 广场樱花枝 GPU 计时对照

相同地面镜头的两份最终版都测到花枝主绘的 GPU 时间增加、团冠主绘的时间下降。四进程未检出新旧花图集在广场重画，单笔绘制的变化无法解释整段 P95 偶发升到 30.8 ms。正式验收的首轮超预算与第二轮通过均保留。

V2 运行源 `eed4fb46`，采集检出 `58a46094`。最终运行源 `1ea97233`。正式反射烘焙还改变了白天和傍晚的两张 `nz.png`，因此整场比较含这两张反射图、花树和对应的贴花缓存标识。直接计时按提交对象追踪广场树。两版静态服务返回的 GLB、材质和批处理等十份输入都与对应的固定源核实，见 `source-proof.json`。

## 四个独立进程

一个 RTX 3060 Laptop GPU，1440 × 900。每次新建原生 Electron 会话，默认傍晚、隐藏 HUD、showInactive、不请求 OS 焦点。先依次预热正式 A/B/C/D 按钮各 1.3 s，再按 A、第三人称真实 W 步行顺序行动两遍，第一遍只观察 RAF，第二遍稀疏计量。A 采 10 s，步行按 W 3.1 s。每次步行开始前六个 RAF 校验出生点及朝向，之后的步距随生产循环推进。稀疏 A 和普通 A 在同一进程里保留不同的人物脚点，时钟模式一致，动画持续推进。不同观测模式间的差值不直接等于插桩开销。系统采样窗口在诊断进程前台的观测为 0 / 203。

## 按实际绘制对象计时

运行时沿真正的批处理输入追踪广场及 W3 的三种部件，并从最终场景提取实际绘制对象。1089 个稀疏采样 RAF 逐帧检查广场三件的独占来源及三角数，每件各命中一次主画面、一次同一盏灯的阴影图，共 6,534 项吻合。花枝材质为 double-sided、alphaTest 0.48、depthWrite 开启，transparent 为 false。广场枝片从 674 增到 2,072 个三角，团冠从 13,680 降到 9,540，树干维持 2,309。树合计净减 2,742 三角，两次真实提交共减 5,484。V2 与 W3 共用 256² 旧图集，最终广场改用独有 512² 图集，W3 继续用旧图。图集内通过截止的像素比例为 21.55% / 24.27%，不能据此换算屏幕填充。

## 复算和复拍

从本目录运行 `node analyze.cjs`、`node crosscheck-trajectory.cjs` 分别重建 `summary.json` 与 `crosscheck-trajectory.json`。原始帧和 timer 位于四个独立目录的 `raw.json.gz`。保留原始 CDP 取消、例外和退出码。系统样本仅保留前台归属、CPU 总量和明确标明的 GPU 计数。

准备两份正常 fixture 后可运行 `node prove-inputs.cjs <V2工作树> <最终工作树> <输出JSON>` 核对真实 URL，按表中顺序运行 `node replay.cjs <Electron可执行文件> <对应fixture目录> <实际顺序标签> <新的输出目录>` 重放相同负载与页内观测。便携入口使用相同的 `flow.cjs`、`page.cjs`、`provenance.cjs`。归档中的 OS / NVIDIA 实测由独立监视器采集，复跑时需要另行采集系统计数。
