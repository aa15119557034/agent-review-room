# 静态阴影实测（X-51 r14 基础上）

## 改动

`src/main.js` 新增两个 URL 开关，**默认行为完全不变**：

- `?shadow=static`：前 3 帧正常渲染阴影贴图，之后 `shadowMap.autoUpdate = false`
- `?shadowEvery=N`：同样进入静态模式，但每 N 帧重烘一次（给会动的物体留补偿）

## 为什么不是降贴图分辨率

先测了三档（G 铁路 / E 港镇，冻结时钟）：

| 档位 | G P95 | E P95 | 绘制调用 |
|---|---|---|---|
| 默认 4096 | 19.48 | 15.58 | 1548 / 1536 |
| 降到 2048 | 20.34 | 13.37 | 1548 / 1536（不变） |
| **静态 4096** | **11.44** | 12.01 | **982 / 972** |
| 静态 + 2048 | 11.76 | **10.05** | 982 / 970 |

**降分辨率几乎没用**（2048 不比 4096 快，调用数还不变）—— 说明阴影 pass 的瓶颈是**顶点与绘制调用**，不是填充率。所以选了「只渲一次」。

## 结果（3 轮中位，每帧 GPU 合计 P95）

| 机位 | 默认 | 静态 | Δ | 调用数 |
|---|---|---|---|---|
| A 主街 | 15.08 | **9.25** | −5.83 | 1614 → 1046 |
| B 便利店 | 13.81 | 10.65 | −3.16 | 1046 → 480 |
| C 后巷 | 13.31 | 10.57 | −2.74 | 989 → 423 |
| D 洗衣店 | 10.01 | 6.45 | −3.56 | 920 → 354 |
| E 港镇 | 14.59 | 10.73 | −3.86 | 1536 → 970 |
| F 山坡 | 10.51 | 7.31 | −3.20 | 778 → 212 |
| G 铁路 | 17.71 | **11.36** | −6.35 | 1551 → 982 |
| H 北端 | 9.72 | 6.02 | −3.70 | 714 → **146** |

**8 个机位全部进入 16.7 ms 以内**（改前 4 个超标）。调用数降 55–80%。

## 画面：冻结时钟下逐像素一致

默认 vs `?shadow=static`，8 机位全部 **0.000%**（A 主街最大通道差 1，其余 0）。

## 代价（必须说清）

- **会动的物体阴影会冻结**。静态模式取第 3 帧的状态；海鸥、行驶的车辆之类的阴影不再跟着动。
- 如果场景里有后加载的物体（异步加载的 GLB），它可能没有阴影。
- 折中方案：`?shadowEvery=N`（例如 30 = 每 0.5 秒重烘一次），代价是每 N 帧多一次阴影 pass。

## 建议

先按 `?shadow=static` 合入，验收时用它；真机上如果发现移动物体的阴影明显违和，再切 `?shadowEvery=30` 或 60。

`?shadowEvery` 的实测还没做 —— 需要的话我补一组（30 / 60 / 120 三档）。
