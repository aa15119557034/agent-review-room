# C酱 第 11 轮：顶棚次峰 + 灯面投影标志

云端 SwiftShader 960×600，道具仍是替身（见 `../c-round9/README.md`）。

## 顶棚次峰（林离逐采样表）
第 10 轮权重 = up × 欧氏距离衰减(L)。顶棚掠射时，墙上像素往下走、固定屏幕半径的外圈采样反而落到离折线更近的顶棚上，
L 变小、衰减权重回升，盖过 up 下降，于是 y313 出现次峰（林离表：tap5 L 1.06→0.63，权重 .18→.91）。
问题不在强度，而在「遮蔽量依赖采样碰巧落在平面的哪一点」。

## 改法：按到遮挡面的距离算
对每个落在另一表面上的采样，取中心点到该采样所在平面的距离 `h = dot(n_s, P - S)`，遮蔽量只取决于 h：
`smoothstep(-.04,0,h) * (1 - smoothstep(0, .48, h))`。墙上像素到顶棚平面的距离就是它离折线的高度，
与采样落点、屏幕半径、L 都无关，所以从折线开始单调变浅。
- h<0（中心在采样面背后，如信箱/绿篱正面后的墙）照旧不计，不回到第 8 轮光环。
- 采样仍须高出中心平面：角度 `smoothstep(.06,.25,cos)` 且高度 `smoothstep(.03,.12,m)`。
  只用角度的第一版（`rejected-v1-…`）把地砖缝、商品正面、面板缝都算成折角，地面出现网格线，所以加了高度门槛。
- L 只保留宽松远端截断（1.2–2 m），折线附近不起作用。
- 强度系数 1.4（最深折角约 70% 遮蔽后再乘 uAO .55）。

同 ROI（960 下 x180..286 红通道 off−on 行均值）：
y186 35.0（顶棚折线）→ y190 21 → y195 14.6 → y200 7.3 → y205 1.3 → y210 起 ≤2，之后归 0。
单峰单调，188–191 之间 ±1 级起伏，是 JPEG/抖动量级。

## 灯面投影
林离指出 `city.js` 末尾统一遍历把所有城镇网格都设成 castShadow=true，覆盖了建造时的 `shadow:false`。
改为保留建造者的标志（gb 分箱、远景房、晾衣）。云端审计 city.root：
`CR:Toon 23, CR:Standard 1, cR:Toon 4, cR:Shader(玻璃) 2, cR:Basic(灯/灯箱) 2`——灯和玻璃不再投影。
另有 4 个 Toon 分箱是上游套件本来就 shadow:false 的部件，现在也不投影了（第 8–10 轮被强制投影），请复核楼体阴影是否有明显变化。

验证：`node scripts/verify.mjs`，Linux 20 步全部 code 0，1507/1507。
