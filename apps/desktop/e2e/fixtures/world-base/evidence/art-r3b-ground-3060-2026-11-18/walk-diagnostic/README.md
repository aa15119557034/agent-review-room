# R3b 第一人称实走慢帧定位

在 `ffbcfa3e` 的三组稀疏记录中，第一人称出现长 RAF 间隔前，渲染调用的主机侧耗时和整帧 GPU 时间均较长。逐帧位置对齐后，三个独立样本组都呈现相同方向。

|匹配样本|15|175|
|生产回调主体，中位 ms|19.2|15.1|
|其中 look.render 主机侧，中位 ms|18.6|14.5|
|整帧 GPU elapsed，中位 ms|16.02|14.45|

慢样本中，人物更新、站区更新、岛屿更新的中位数分别为 0.1、0.4、0.2 ms。3 组中，慢/常样本的渲染主机耗时中位分别是 18.6/14.3、18.2/14.3、20.2/14.9 ms。下一阶段若继续定位，应给同一位置的世界彩色绘制、每盏投影光的 shadow pass、后处理分别做稀疏 GPU 查询，对照未插桩实走。各阶段嵌套关系须拆成互斥 GPU 查询。现有观测不能将主机侧渲染时间细分为 JS、图形命令提交、驱动同步或 GPU 排队，也不包含最终屏幕呈现时刻。

## 实机口径

两进程均使用独立干净 R3b 工作树、正常傍晚入口、RTX 3060 Laptop、1440×900、DPR 1。依次以 A–D 原机位预热，各 11.3 秒。每进程重复三次第三人称按 W 约 3.1 秒，再原地切第一人称继续约 3.1 秒。一进程按控制/稀疏/控制排列，另一进程按稀疏/控制/稀疏排列。窗口以 `showInactive` 打开，原生 Chromium 输入事件只发至测试页。24 次 down/up 均由页面识别为可信事件。74 个整机前台采样均在测试进程树外，DOM 焦点端点单列于报告。三次首人称控制测得 47.56、64.36、55.44 FPS，P95 为 30.8、15.5、30.8 ms；该诊断与原四轮正式验收分开。

每次第三人称从相同脚位启动，初始 yaw 4°、pitch −8°。源码 `setPose` 清除速度，6 个连续 RAF 观测校验静置位置。切第一人称前后同一调用中的脚位精确相等。实际第一人称起点之间最大差 0.087 m，终点之间最大差 0.143 m。统计只使用所有其余同视角重复中都找到 0.12 m 以内脚位的区间。末次松键后静置 1.25 s，再取六帧验证余速衰减，位移小于 0.0001 m。

控制只采 RAF、脚位、相机与渲染计数。稀疏模式约每三帧包裹一次生产 RAF，记录各阶段起止时间、该回调退出和下一回调入口，在整段生产回调的 GPU 命令两端挂异步计时查询。合计 2,183 个 RAF 间隔、373 个稀疏回调、373 个有效 GPU 查询，disjoint 为 0。本文将回调配给下一 RAF 间隔，主机和 GPU 时间会重叠，不能相加。系统负载每约半秒采样，不能逐帧拆因。

## 独立复算

在此目录运行 `node analyze.cjs --browser-only`，可仅从两份浏览器原始记录复算。程序把每个稀疏生产回调配给同一段内下一个真实 RAF 间隔，再把该回调的脚位与其余五次同视角实走逐一比对。每次实走都须有一帧在 0.12 m 水平半径内。第一人称得到 190 个可比回调，其中 15 个下一间隔超过 20 ms，175 个正常；第三人称为 180 个，其中 23 个超过 20 ms。程序还输出两组的阶段中位、GPU 中位、超出 15.4 ms 的数量与三次控制的实际 FPS/P95。

`node analyze.cjs` 会另外解压 [Windows 与 GPU 的匿名原始样本](system-samples.json.gz)。Windows 监视器约每 500 ms 取一次系统前台窗口，判断其拥有进程是否属于该测试进程树。公开文件保留采样时刻、布尔判定、拥有者是否已识别及数值负载；复算按原始浏览器记录的各段起止壁钟重新关联。74 次均识别到窗口拥有者，0 次属于测试进程树。两份浏览器记录自身只包含 DOM 焦点，系统前台总数来自这个独立样本文件。

`node analyze.cjs --json` 输出完整分组统计。`node verify.cjs` 校验三份原始文件哈希，将从头重算的逐段、同位、各回调阶段和空间分组与[归档汇总](comparison.json)逐字段核对。两条分析命令均不读取归档汇总，验证命令只在复算之后比较结果。
